# KRAY Web3 integration — dogarmy.space

Source of truth: https://www.kray.space/developers (studied 2026-07-03; re-check before relying on anything not listed here).

## Hard constraints (learned the hard way)

1. **CORS allowlist**: every browser `fetch` to `kray.space` (both `/api/*` and `/l2/*`) with a foreign `Origin` returns **HTTP 500**. ALL reads/writes go through our Vercel functions in `api/` (server-side requests send no Origin and work). Never add kray.space to `connect-src`.
2. **CSP** ([vercel.json](../../vercel.json)): `script-src 'self'` + inline hashes — page JS must live in external root files (like `web3.js`, `wallet.js`). `img-src` allows `https://www.kray.space` (thumbnails). Canvas work needs same-origin images → use `/api/thumb?id=` proxy (cross-origin images taint the canvas).
3. **`api.kray.space`** (the "official" base URL in the docs) requires a partner API key. The **same endpoints work keyless on `www.kray.space`** — that's what we use.
4. Vercel functions: files in `api/` starting with `_` are not routes (shared helpers live in [api/_kray.js](../../api/_kray.js)).

## Wallet extension (`window.krayWallet`)

- `requestAccounts()` → `{success, address, publicKey}` (popup; first visit per origin shows a Connection Request approval).
- `connect()` → silent variant. `getAccounts()` → `['bc1p...']`. `getPublicKey()` → **plain hex string** (x-only, 64 chars), not an object.
- `getFullWalletData()` → `{address, balance(sats), inscriptions[], runes[]}`. Rune amounts: `{rawAmount, divisibility}` or `{amount:{amount,divisibility}}` or plain `amount` — see `runeAmount()` in [web3.js](../../web3.js). DOG rune name may carry a trailing emoji; match letters only against `DOGGOTOTHEMOON`.
- `signMessage(msg)` → `{signature(128 hex Schnorr BIP-340), address}`. Auto-signs non-sensitive messages when unlocked. Sensitive ones (L2 tx format `addr:...`, `scroll_*`, `KRAY:*`) ALWAYS popup.
- `signMessageWithConfirmation(msg)` → same signature, always popup. Use for anything that moves value.

## L2 "Origin Layer" (keyless base: `https://www.kray.space`)

- `GET /l2/health`, `GET /l2/account/:addr/balance` → **KRAY (gas token) only**: `{balance, balance_kray, staked, locked, available, nonce, ...}` (all display units; `nonce` = L2 tx count). `GET /l2/transaction/recent`, `GET /l2/transaction/:id`, `GET /l2/tokens`.
- `GET /l2/account/:addr/balances` (verified 2026-07-06) → **ALL non-zero token balances**: `{success, account, balances:[{token_symbol, token_name(spaced rune), emoji, balance(raw string), divisibility}]}`. Self-describes divisibility, omits zero balances, only meaningful for bc1p taproot accounts (L2 derives at m/86'). This is what powers the DogScan address view's "Origin Layer balances" panel (ride-along in `api/scan.js`, best-effort). The singular `/balance` endpoint returns KRAY only — use `/balances` for the full per-token list.
- **Token divisibility** (`/l2/tokens`): KRAY=0, DOG=5 (raw 1000000 = 10 DOG), DSC=0, **RADIOLA=2** (confirmed live 2026-07-06 — earlier "0" was wrong; `dogscan.js` TOKEN_DIV already had 2). KRAY tx amounts are display units; DOG amounts are raw — divide by 1e5. Prefer the `divisibility` field the `/balances` endpoint returns over any hardcoded table.
- Send: `POST /l2/transaction/send` with `{from_account, to_account, amount(string), tx_type:'transfer', token_symbol, signature, pubkey, nonce, memo?, data?}`. Signed message format: `` `${from}:${to}:${amount}:${nonce}:transfer` ``. Gas = 1 KRAY, always, to treasury `bc1p5u00mjuxy0c040t9jdvcjxmzjsy2yluzukdzkta0fnu0hc5m29aqhk3nhv`.
- Custom apps: always `tx_type:'transfer'` + your semantics in `data: JSON.stringify({app, action, ...})`.

## Ordinals / collection verification (on-chain provenance)

- `GET /api/wallet/:addr/inscriptions` → `{inscriptions:[{id, content_type, ...}]}` (no parent info).
- `POST /api/ordinals/properties/batch` `{inscription_ids:[≤50]}` → `properties[id].parents[]`.
- Collection = children of a parent inscription. **DOG•SOCIAL•CLUB parent: `8a18494da6e0d1902243220c397cdecf4de9d64020cf0fa9fa16adfc6e29e4eci0`** (306 items, image/png). **Runestone parent: `fdb2df5d2b16db1ebcbf09e2d23b3f4e417db44b58e712c99b61f26b52c7cbb5i0`** (112k items, `model/gltf+json` — NEVER filter by image type when checking).
- Thumbnails: `GET /api/rune-thumbnail/:inscriptionId` (small PNG, hotlink-ok). Same-origin proxy: `/api/thumb?id=`.
- `GET /api/collections` → registry with parentIds. `GET /api/dashboard/avatar/:addr` → user's chosen Kray profile avatar.

## Dev Scrolls (escrow-paid mission rewards)

- Created in Kray's Dev Studio (wallet must be whitelisted in `l2_authorized_creators` — ask the KRAY team, they sponsor the army). Pool goes to ESCROW; you get a 64-hex `scroll_key` — **secret, backend only** (env `KRAY_SCROLL_KEY`).
- Pools can hold **KRAY, DOG, DSC or RADIOLA** (`pool_token`); claim modes `open`/`single`; `fixed` or `dynamic` reward.
- User claim message (canonical): `` `scroll_claim:reward:${userAddress}:${Date.now()}` `` → signed by user → backend POSTs `/api/dev-scroll/claim` with `{scroll_key, user_address, user_pubkey, user_signature, user_message}` → escrow pays.
- Status: `GET /api/dev-scroll/info/:key`, `GET /api/dev-scroll/check-claim/:key/:addr`. Manage: `/edit` (top-up), `/fund` (anyone can add tokens), `/toggle`, `/remove`.

## Explorer endpoints (keyless on www.kray.space, power /dogscan)

- `GET /api/explorer/tx/:txid` → `{tx(vin+prevout,vout), block, inscriptions, runes, analysis(fee,feeRate,vsize,confirmations)}` — vout values in sats.
- `GET /api/explorer/address/:addr` → `{bitcoin{confirmed,unconfirmed,total}, utxos[], inscriptions[], runes[{name,amount(raw),divisibility,symbol,utxos[]}], transactions[]}`.
- `GET /api/explorer/inscription/:idOrNumber` → `{inscription{...charms[],parents[],children[]}}`. `GET /api/explorer/rune/:idOrName` (accepts `840000:3`, `DOGGOTOTHEMOON`, spaced names) → `{rune{supply{},etching{},holders{total,top[]}}}`.

## KRAY Social feed (keyless on www.kray.space, verified 2026-07-06)

- `GET /api/social/feed/trending?limit=21` and `/api/social/feed/recent?limit=21` → `{success, posts:[{id, is_l2, content, likes_count, comments_count, created_at, repost_* ...}]}`.
- L1 post: `inscription_id` = poster's profile inscription (avatar = `/api/rune-thumbnail/:id` or `/api/ordinals/:id/content`). L2 post: `nft_id`/`l2_nft_id` + `nft_image` (Supabase URL `wokhgoabtwuvqynogafv.supabase.co` — NOT in our img-src CSP; route through `/api/thumb?u=`).
- Post/profile page: `https://www.kray.space/inscription-profile?id=<inscription_id | nft_id>`.
- `content` is user-generated — always insert with textContent, never innerHTML.

## DAO Room (keyless on www.kray.space, discovered 2026-07-06 from the dao-room page source)

- Base: `GET /api/dao/<encoded spaced rune>/...` — `messages?limit=50`, `proposals`, `members`, `permissions?address=`, `council`; POST `message` `{address, content, weight}` (NO signature — kray's own chat send is trust-based + WebSocket for live), `verify`, `heartbeat`, `leave`, `proposals/:id/vote`.
- Message shape: `{id, sender, senderShort, weight, weightFormatted, content, timestamp(ISO), role, hasNft, nftThumbnail, weightRank}`. Weight = % of rune supply (DOG: amt/1e9 for display units).
- Room page: `https://www.kray.space/dao-room?rune=DOG%E2%80%A2GO%E2%80%A2TO%E2%80%A2THE%E2%80%A2MOON`.
- Native posting IS supported (2026-07-06): `api/dao.js` also handles POST `{what:'verify'|'message'}`. Flow: wallet signs `DAO:<NORMALIZED_RUNE>:<ts>` (letters only, e.g. `DAO:DOGGOTOTHEMOON:<ts>`) → `POST /api/dao/<rune>/verify {address,pubkey,signature,timestamp}` opens a server-side session → `POST /api/dao/<rune>/message {address,content,weight}`. The message send is trust-based, but kray's `/message` rejects "Session expired" without a recent verify, and "Signature expired" if the signed ts is stale. kray keeps the session warm via WebSocket + `/heartbeat`; our mirror doesn't, so after idle the first re-post can 502 "Session expired" and self-heals on retry (web3.js resets `daoVerified` in the catch). UI still deep-links to kray's room for proposals/voting.

Fails open on a check-claim blip (won't block honest first-timers; the quiz still gates bots). Not a hard on-chain guarantee against a burst of truly-concurrent claims, but paired with the quiz + the 15-min-fresh signed message it stops casual repeat/drain. A short-lived creator-signed `/edit` relay + `/scroll-admin` page were built to try the native toggle, then removed once the immutability was confirmed.
